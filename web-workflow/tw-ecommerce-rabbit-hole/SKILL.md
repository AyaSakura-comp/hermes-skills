# TW E-commerce Rabbit Hole Avoidance

當瀏覽台灣電商網站（PChome、MOMO、蝦皮等）時，遵循此 skill 避免陷入交互死胡同。

## 🚫 三大禁忌

### 1. 灰色按鈕不能按

- **視覺判斷**：按鈕是灰色、半透明、或帶 `disabled` 屬性的 → **不要點擊**
- **DOM 確認**：snapshot 輸出中如果看到 `disabled="true"` → 確定不可互動
- **灰色 = disabled = 無效點擊**，白浪費時間

### 2. PChome 數量調整 ≠ 正常邏輯

PChome 購物車的「＋」按鈕行為是**複製一筆相同商品**，不是增加數量：

| 操作 | 實際效果 |
|------|----------|
| 按「＋」 | 新增一筆相同商品（各 1 件） |
| 想「數量 1→2」 | **做不到**，除非進編輯模式 |
| 編輯模式裡的「＋」 | 通常是灰色 disabled，無法點擊 |

**解決方式**：如果需要在 PChome 調整數量，手動在瀏覽器操作，或使用 JavaScript 直接修改 DOM。

### 3. 跟着引導走，不要自己亂跳

台灣電商網站的導航邏輯通常有明確的步驟：

**標準流程**：
```
首頁 → 搜尋商品 → 商品頁 → 加入購物車 → 購物車 → 結帳
```

**不要做的事**：
- ❌ 在購物車頁面直接按商品連結跳回商品頁
- ❌ 在商品頁直接跳購物車
- ❌ 在結帳流程中亂點返回或跳到別頁
- ❌ 試圖用 vision-mark 精確點擊灰色按鈕

**正確做法**：
- ✅ 從首頁開始，跟着網站的引導流程走
- ✅ 每個步驟完成後，看下一個明確的按鈕（通常是藍色或亮色）
- ✅ 如果卡在灰色按鈕，換個思路（手動操作或用 JS）

## 🔍 診斷清單

當你在台灣電商網站卡住時，檢查：

1. **按鈕是灰色嗎？** → 不能按，換個方式
2. **DOM 有 `id` 屬性嗎？** → 如果沒有，用 snapshot 找 aria-label 或 text
3. **網站行為是否符合預期？** → 特別注意「＋」按鈕，PChome 會複製商品
4. **我是不是跳頁了？** → 回到引導流程的下一步
